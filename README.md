# DELIPAS — ระบบรับ–ส่งเอกสารและลายเซ็น

เว็บแอปสำหรับเปิด ticket ที่สร้างและมอบหมายงานไว้ใน monday ให้ผู้เกี่ยวข้องเซ็นผ่านมือถือ แล้วแนบหลักฐานและเปลี่ยนสถานะของ ticket เดิม

## ความสามารถ

- แสดงรายการตามวันที่ดำเนินการ ตั้งแต่วันนี้ย้อนหลัง 30 วัน ตามเวลาไทย เรียงล่าสุดก่อน ครั้งละ 25 รายการ
- กรองงานรอดำเนินการ งานบันทึกผลแล้ว หรือทั้งหมดในช่วงวันที่ดังกล่าว
- ค้นหาภายในรายการที่โหลดแล้ว และโหลดรายละเอียดเมื่อเปิด ticket
- เซ็นด้วยนิ้ว ปากกา หรือเมาส์ พร้อมชื่อผู้เซ็น
- เลือกผลรับครบ รับไม่ครบ หรือไม่ได้รับ/ไม่ได้ส่งมอบ
- สร้างลิงก์เซ็นเฉพาะ ticket ผู้ถือครองลิงก์ใช้งานได้โดยไม่ต้องล็อกอิน ลิงก์หมดอายุ 1 ชั่วโมงนับจากโหลดรายละเอียด ticket
- เก็บฉบับร่างในเบราว์เซอร์ และส่งข้อมูลเดิมซ้ำเมื่อยังไม่ยืนยันผลการบันทึก

รายการไม่มีวันที่ วันที่อนาคต และวันที่เก่ากว่าช่วงที่กำหนดจะไม่แสดงในรายการ ค้นหาไม่ได้ค้นทั้งบอร์ด การเซ็นและบันทึกต้องใช้อินเทอร์เน็ต

## ขั้นตอนใช้งาน

1. สร้าง ticket และมอบหมายผู้รับผิดชอบใน monday
2. ผู้รับผิดชอบเข้าสู่เว็บและเลือกรายการ
3. ให้ผู้เกี่ยวข้องเซ็นบนเครื่อง หรือกด **สร้างลิงก์ให้ผู้เซ็น** แล้วส่งลิงก์
4. ระบุชื่อ เลือกผล และเซ็นก่อนกด **บันทึกใน monday**
5. รอข้อความยืนยันว่าบันทึกแล้ว หากเกิดข้อผิดพลาดให้ดูข้อความ และส่งข้อมูลเดิมซ้ำตามที่ระบบเสนอ

ระบบอ่านรายการล่าสุด อัปโหลดหลักฐาน PNG ตรวจสถานะอีกครั้ง แล้วจึงเปลี่ยนสถานะ การอัปโหลดกับเปลี่ยนสถานะเป็นคนละคำขอ จึงอาจสำเร็จเพียงบางขั้นตอน ระบบใช้ request ID และชื่อไฟล์ช่วยตรวจการส่งซ้ำ

## เทคโนโลยี

React 19, TypeScript, Vinext/Vite, Tailwind CSS, Cloudflare Workers และ monday GraphQL API มี service worker สำหรับไฟล์ไอคอนและ manifest เท่านั้น ไม่ได้แคชข้อมูล ticket หรือรองรับบันทึกแบบออฟไลน์

## เริ่มพัฒนาในเครื่อง

ต้องมี Node.js 22.13 ขึ้นไป และ npm

```sh
npm ci
```

คัดลอก `.env.example` เป็น `.env.local` แล้วใส่ token:

```dotenv
MONDAY_API_TOKEN=your_monday_api_token
```

```sh
npm run dev
```

เปิด URL ที่เซิร์ฟเวอร์แสดง โดยปกติคือ `http://localhost:3000` การเข้าสู่ระบบในเครื่องพึ่งพาตัวช่วยของ Sites plugin และอาจต่างจากโฮสต์จริง

## ตั้งค่า monday

โปรเจกต์ปัจจุบันจำกัดการทำงานไว้ที่บอร์ด DEV `5031213491` และรายการหลัก ไม่รวม subitem

| ค่า | ตำแหน่ง |
| --- | --- |
| Board ID | `BOARD` ใน `lib/monday.ts` |
| คอลัมน์สถานะ | `single_select_1` |
| คอลัมน์หลักฐาน | `signature` ชนิด File |
| คอลัมน์วันที่ดำเนินการ | `date` |

สถานะที่ตรวจสอบกับบอร์ด:

| Index | ชื่อสถานะ |
| --- | --- |
| 0 | รับเอกสารไม่ครบถ้วน |
| 1 | ได้รับเอกสารครบถ้วน/ส่งมอบเอกสารแล้ว |
| 2 | ไม่ได้รับเอกสาร/ไม่ได้ส่งมอบเอกสาร |
| 5 | รอดำเนินการ |

คอลัมน์อื่นของบริษัท ผู้ติดต่อ และรายละเอียดเอกสารถูกกำหนดใน `lib/monday.ts` หากเปลี่ยนบอร์ดต้องตรวจ mapping ทั้งหมด Token ต้องมีสิทธิ์อ่านรายการ อัปโหลดไฟล์ และแก้สถานะ การจำกัด Board ID ในโค้ดไม่ได้ลดสิทธิ์ของ token ที่ monday ออกให้

## Build และทดสอบ

```sh
npx tsc --noEmit
node --test tests/monday.test.mjs tests/recent-items.test.mjs
npm run build
npm start
```

`npm start` ใช้ Wrangler เปิดผล build สำหรับตรวจในเครื่อง ไม่ใช่คำสั่ง deploy production ชุดทดสอบตรวจการเซ็น context การส่งซ้ำ ลำดับอัปโหลด/เปลี่ยนสถานะ การป้องกันเขียนทับ และช่วงวันที่ ไม่ได้เขียนข้อมูลลง monday จริง

## Deploy และข้อจำกัดของโฮสต์

โปรเจกต์นี้สร้างสำหรับ **Sites บน Cloudflare Workers** ไม่ใช่เว็บ static และไม่ได้พร้อมใช้บนทุกโฮสต์โดยไม่ปรับแก้

- `.openai/hosting.json` อ้างอิง Sites project เดิมของเจ้าของ การ fork ไม่ได้ให้สิทธิ์ deploy ไปที่ project นั้น
- ตั้ง `MONDAY_API_TOKEN` เป็น secret ใน production runtime แยกจาก `.env.local` ห้ามส่ง token ไปเบราว์เซอร์หรือใช้ตัวแปร `VITE_`/`NEXT_PUBLIC_` สำหรับ token
- โฮสต์ต้องรัน server routes `/api/items` และ `/api/handoffs` รวมทั้งรองรับ `cloudflare:workers`
- หน้ารายการใช้ header `oai-authenticated-user-id` จากแพลตฟอร์ม และขั้นตอน sign-in ของ Sites
- `/signin-with-chatgpt`, `/signout-with-chatgpt` และ `/callback` เป็นเส้นทางที่แพลตฟอร์มดูแล ไม่มี route เหล่านี้ในแอป
- หากย้ายไปโฮสต์อื่น ต้องปรับ runtime bindings และระบบ authentication/authorization ห้ามแก้ด้วยการเชื่อ header ที่ผู้ใช้ส่งเองหรือเปิดรายการทั้งหมดโดยไม่ตรวจสิทธิ์
- ตรวจการอนุญาตผู้ใช้ก่อนใช้จริง: โค้ดหน้ารายการปัจจุบันตรวจว่าล็อกอินแล้ว แต่ยังไม่มี allowlist ผู้รับผิดชอบเฉพาะบุคคลในตัวแอป

ลิงก์เซ็นเป็นสิทธิ์เข้าถึง ticket ใครถือครองลิงก์สามารถอ่านและส่งผลของ ticket นั้นได้จนหมดอายุ จึงควรส่งเฉพาะผู้เกี่ยวข้อง

## แก้ปัญหา

| อาการ | จุดที่ควรตรวจ |
| --- | --- |
| ใช้ในเครื่องได้ แต่โฮสต์อ่าน monday ไม่ได้ | ตรวจ production secret, Workers runtime และ server routes |
| 401 | ยังไม่มี session/header ยืนยันตัวตนสำหรับหน้ารายการ |
| 403 บน dev tunnel | ตรวจ response body ว่ามาจาก tunnel หรือแอป รุ่นเก่าเคยตรวจ Origin ไม่ตรงกับ URL ภายใน ปัจจุบัน public handoff ใช้ signed context |
| `/signin-with-chatgpt` ตอบ 404 | ตรวจระบบ sign-in ของแพลตฟอร์มและการตั้งค่าโฮสต์ ไม่ใช่หลักฐานว่า monday token ผิด |
| 409 | context หมดอายุ ข้อมูล ticket เปลี่ยน หรือโครงสร้างคอลัมน์ไม่ตรง ให้เปิดตรวจข้อมูลใหม่ |
| 503 | ไม่พบ `MONDAY_API_TOKEN` ใน runtime |
| ยังไม่ยืนยันว่าบันทึกครบ | อาจสำเร็จบางขั้นตอนแล้ว ใช้ส่งข้อมูลเดิมซ้ำเพื่อให้ระบบตรวจหลักฐานเดิม |
| โหลดช้า | ตรวจเวลา monday API และเครือข่าย หากใช้ dev tunnel ยังพึ่งเครื่องและอินเทอร์เน็ตของผู้เปิด tunnel |

ตรวจพบ sign-in 404 ใน production log ระหว่างพัฒนา แต่ทดสอบอ่าน ticket ด้วยลิงก์เซ็นได้ ยังต้องทดสอบ flow ล็อกอินและบันทึกลายเซ็นครบขั้นตอนในสภาพแวดล้อมที่จะนำไปใช้งานจริง

```text

app/api/handoffs/route.ts รับคำขอบันทึก

lib/monday.ts            monday API, mapping, date filters, retry logic
lib/runtime.ts           runtime secret และการตรวจสิทธิ์
tests/                   การทดสอบ logic
```
